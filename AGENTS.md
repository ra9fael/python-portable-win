# AGENTS.md

This file provides guidance to Ai Code Agents when working with code in this repository.

## Overview

Portable, self-bootstrapping Python environment for Windows. Ships standalone Python apps without host Python dependency. Uses Python embeddable engine + patched site-packages + isolated pip/uv.

## Architecture

```
scripts/          # PowerShell engine — all core logic lives here
  bootstrap.ps1   # Downloads embeddable Python, patches ._pth (import site), installs pip + setuptools + wheel
  activate.ps1    # Sources env into current shell (PYTHONNOUSERSITE=1, VIRTUAL_ENV set, PATH prepended)
  pip.ps1         # Isolated pip wrapper (forces PYTHONNOUSERSITE=1, isolated cache in python\.pip_cache)
  run.ps1         # App launcher — menu mode (lists .py files) or direct passthrough (-TargetScript)
  add_tkinter.ps1 # Downloads/extracts tcltk.msi matching the embeddable Python version
  build_release.ps1 # Streams workspace into distributable ZIP: wraps .exe as relative-path .bat, patches extensionless shebangs, excludes caches
python/           # (Git-ignored) Windows embeddable Python — generated by bootstrap.ps1
hello/            # Example app directory — reference pattern for new apps
```

**Key design decisions:**
- `python/` is git-ignored. Bootstrap re-creates it on any clone.
- The `._pth` file in the embeddable Python is patched to un-comment `import site`, enabling regular `site-packages`.
- `activate.ps1` is dot-sourced (`. .\scripts\activate.ps1`), not executed directly. It defines a `deactivate` function to undo env changes.
- setuptools and wheel are installed during bootstrap so sdist-only packages (e.g. gym) can build.
- App `.bat` wrappers call `run.ps1` via `PowerShell.exe -NoProfile -ExecutionPolicy Bypass`.

## Common Commands

```powershell
# First time: build the python/ environment
.\scripts\bootstrap.ps1

# Install packages (isolated)
.\scripts\pip.ps1 install <package>

# Activate for interactive dev (dot-source required)
. .\scripts\activate.ps1
# Then: python, jupyter, pytest, etc. work normally
deactivate  # restores host env

# Add Tkinter support to the portable env
.\scripts\add_tkinter.ps1

# Build distributable ZIP
.\scripts\build_release.ps1
```

## Adding a New App

1. Create a directory (e.g., `my_app/`)
2. Write `main.py` (or multiple `.py` scripts)
3. Add a `.bat` wrapper:
   - **Menu mode**: `PowerShell.exe -NoProfile -ExecutionPolicy Bypass -File "%~dp0..\scripts\run.ps1" -AppDir "%~dp0."`
   - **Direct mode**: Add `-TargetScript "main.py"` to the above

## Moving the Workspace

`python/Scripts/*.exe` launchers and extensionless scripts (e.g. `numba`, `jsonpointer`) embed the absolute path to `python.exe`, so they break after the workspace moves. Options:

- Re-run `.\scripts\bootstrap.ps1` to rebuild the environment (it can restore packages from `requirements.txt`).
- Distributable ZIPs are unaffected: `build_release.ps1` deletes the `.exe` launchers, generates relative-path `.bat` wrappers from entry_points metadata, and rewrites extensionless-script shebangs to `#!..\python.exe`.

## Python Version Upgrade

1. Edit `$Version` in `scripts\bootstrap.ps1`
2. Run `.\scripts\bootstrap.ps1` — it auto-exports current packages to `requirements.txt` and offers to restore them after the engine replacement
