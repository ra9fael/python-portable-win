# AGENTS.md

This file provides guidance to Ai Code Agents when working with code in this repository.

## Overview

Portable, self-bootstrapping Python development environment for Windows. No host Python dependency. The runtime is either python-build-standalone (installed via `uv`, includes Tcl/Tk) or the official embeddable engine with a patched `._pth`. The normal entry point is `python.exe` itself — activate the shell or point the IDE at `python/python.exe`. `App.exe` is an optional sample of shipping an app through this environment (`bootstrap.ps1 -WithLauncher`).

## Architecture

```
App.exe            # (Optional) sample launcher; reads app.ini, resolves paths from its own dir
app.ini            # [app] module / gui / app_dir configuration for App.exe
scripts/           # PowerShell engine — all core logic lives here
  bootstrap.ps1   # Installs PBS via uv (or embeddable), prepares pip, installs the startup hook, builds shim.exe
  activate.ps1    # Sources env into current shell (PYTHONNOUSERSITE, PATH, Tcl/Tk, caches, JUPYTER_DATA_DIR) and repairs stale launchers
  pip.ps1         # Isolated installer: uv pip when available, otherwise python -m pip; repairs launchers afterwards
  run.ps1         # Optional dev menu (not used by the packaged app)
  add_tkinter.ps1 # Adds tcltk.msi to the embeddable engine; skips when Tcl/Tk exists (-Force to reinstall)
  build_launcher.ps1 # Compiles launcher/Shim.cs with csc.exe; Launcher.cs (App.exe) unless -ShimOnly
  repair.py       # Importable: rebuilds console-script shims for the current location
  sitecustomize.py # Copied into site-packages; runs repair on interpreter start when the root changed
  checksum.ps1    # Shared SHA256 helpers dot-sourced by bootstrap/add_tkinter
  checksums.psd1  # Pinned hashes for engine, get-pip and tcltk downloads
  update_checksums.ps1 # Refreshes checksums.psd1 for a version/arch matrix
  new-portable-project.ps1 # Scaffolds app/scripts/multi profiles for a new project
  workspace.ps1   # Resolves -Workspace and stages runtime scripts for consumer builds
  build_release.ps1 # Streams workspace into a ZIP with shim.exe (+ App.exe when present), excludes caches
scripts/launcher/ # Launcher.cs (App.exe, optional) and Shim.cs (console-script shim)
templates/consumer/ # build-portable.ps1 template used by new-portable-project.ps1
templates/scripts/  # build.ps1 / start.bat / main.py templates for -Profile scripts
scripts/bin/      # (Git-ignored) compiled shim.exe — the repair payload
python/           # (Git-ignored) generated Python environment
hello/            # Example app directory — reference pattern for new apps
docs/             # Bilingual architecture and troubleshooting (zh is the default)
skills/           # Agent-facing skill: portable-python-env
.github/workflows/selftest.yml # Windows CI: embeddable bootstrap → shim → selftest
```

The full rationale for the repair design lives in `docs/en/architecture.md`; task recipes for agents live in `skills/portable-python-env/SKILL.md`. Keep this file focused on repository conventions rather than repeating them.

**Key design decisions:**
- `python/` is git-ignored. Bootstrap re-creates it on any clone.
- PBS mode removes `Lib/EXTERNALLY-MANAGED` (PEP 668) because the package owns the interpreter.
- Embeddable mode patches `._pth` to un-comment `import site`, enabling regular `site-packages`.
- `App.exe` is optional. It resolves paths from its own directory, sets `PYTHONNOUSERSITE`, `PYTHONPATH`, and `TCL_LIBRARY`/`TK_LIBRARY`, and hides its console for GUI apps.
- Console-script `.exe` files generated by pip/uv embed absolute paths. `repair.py` replaces them with `scripts/bin/shim.exe` copies plus `<name>.entry` sidecars. Triggered on four paths: `pip.ps1` right after install, `activate.ps1` on dot-source, and `sitecustomize.py` on interpreter start (marker mismatch) and exit (freshly written `.exe` files). No launcher is required.
- `repair.py` also creates missing launchers from `entry_points.txt`, so `pip.exe` exists even though PBS never ships it.
- `sitecustomize.py` appends `python` and `python/Scripts` to child-process `PATH`, sets the embeddable engine's `TCL_LIBRARY`/`TK_LIBRARY`, and defaults `PIP_USER=0`, `PIP_CACHE_DIR`, `PIP_CONFIG_FILE`.
- `activate.ps1` sets `UV_SYSTEM_PYTHON=1`, `UV_PYTHON`, `UV_CACHE_DIR` so a bare `uv pip install` targets the package interpreter.
- Launchers are identified by content (`UV_TRAMPOLINE_KIND`, appended `__main__.py` zip), not by file size, so real binaries such as `ruff.exe` are never overwritten.
- Missing entry-point metadata is recovered from the launcher's own `__main__.py` payload, so packages without `dist-info` are still portable.
- `activate.ps1` is dot-sourced (`. .\scripts\activate.ps1`), not executed directly. It defines a `deactivate` function to undo env changes.
- setuptools and wheel are installed during bootstrap so sdist-only packages (e.g. gym) can build.
- Bootstrap stages the engine under `python.new` and verifies downloads against `scripts/checksums.psd1` before swapping, so a failed or tampered download leaves `python/` intact. `-PythonSha256` / `-GetPipSha256` override, `-SkipChecksum` bypasses.
- The actual installed patch version is recorded in `python/.portable_version`; a later bootstrap without `-Version` reuses it.
- `pip.ps1` rejects `--user`, restores the project `sitecustomize.py` after install if a package replaced it, and maps `PIP_INDEX_URL` / `PIP_FIND_LINKS` to their `UV_*` equivalents.
- `pip.ps1 lock` produces a hash-pinned `requirements.lock`; bootstrap prefers it over `requirements.txt`.
- `build_release.ps1 -Wheelhouse` collects installed dependencies into `wheels/`; `sitecustomize.py` and `activate.ps1` set `PIP_FIND_LINKS` so offline installs work.
- Consumer mode: `-Workspace <dir>` makes every script operate on an external workspace (convention: `<app>/.portable`) instead of `scripts/..`. `workspace.ps1` resolves the path and stages `repair.py`, `sitecustomize.py`, and `bin/shim.exe` there, so a submodule checkout is never written to. `new-portable-project.ps1` generates the app-level glue from `templates/consumer/build-portable.ps1`. Default behaviour is unchanged when `-Workspace` is omitted.
- Scaffold profiles: `app` (default; submodule + root `.portable`), `scripts` (copies `scripts/` into the project, no submodule; code in `my_tools/`, build via `scripts/build.ps1`), and `multi` (submodule + one `scripts/build-<app>.ps1` per app, each with `<app>/.portable`). The staging copy skips the workspace when it sits inside the app directory, so `multi` never copies `.portable` into itself.

## Common Commands

```powershell
# First time: build the python/ environment, startup hook and shim
.\scripts\bootstrap.ps1
.\scripts\bootstrap.ps1 -Engine embeddable    # force the official embeddable engine
.\scripts\bootstrap.ps1 -Engine pbs           # force python-build-standalone via uv
.\scripts\bootstrap.ps1 -WithLauncher         # also build the optional App.exe sample
.\scripts\bootstrap.ps1 -NonInteractive       # CI/unattended: never prompt
.\scripts\bootstrap.ps1 -Mirror <url> -PipIndexUrl <url>   # restricted network
.\scripts\bootstrap.ps1 -SkipChecksum         # trusted offline artifact only

# Install packages (isolated; uses uv pip when available; repairs launchers)
.\scripts\pip.ps1 install <package>
.\scripts\pip.ps1 install -r requirements.txt
.\scripts\pip.ps1 lock                        # requirements.* -> requirements.lock (hashes)

# Activate for interactive dev (dot-source required) — this is the normal entry
. .\scripts\activate.ps1
# Then: python, jupyter, pytest, etc. work normally
deactivate  # restores host env

# Rebuild shim only (needed by repair.py), or shim + App.exe
.\scripts\build_launcher.ps1 -ShimOnly
.\scripts\build_launcher.ps1

# Run the optional sample launcher
.\App.exe
.\App.exe --module my_app.gui
.\App.exe --script my_app\main.py

# Add Tkinter support to the embeddable engine (PBS already includes it)
.\scripts\add_tkinter.ps1

# Refresh download hashes after a new Python patch release or get-pip update
.\scripts\update_checksums.ps1 -Version 3.14.10 -Arch amd64,arm64,win32

# Consumer mode: build a project workspace (e.g. <app>\.portable) from a submodule
.\scripts\new-portable-project.ps1 -ProjectRoot <app> -AppDir app -Requirements requirements.txt -Version 3.12.10
.\scripts\new-portable-project.ps1 -Profile scripts -ProjectRoot <app> -AppDir my_tools
.\scripts\new-portable-project.ps1 -Profile multi -ProjectRoot <suite> -AppDirs apps/one,apps/two
.\scripts\bootstrap.ps1 -Workspace <app>\.portable -Engine embeddable -Version 3.12.10
.\scripts\pip.ps1 -Workspace <app>\.portable install -r <app>\requirements.txt
.\scripts\build_release.ps1 -Workspace <app>\.portable

# Build distributable ZIP (optionally with an offline wheelhouse)
.\scripts\build_release.ps1
.\scripts\build_release.ps1 -Wheelhouse

# Self-test the relocation machinery (temp copy, no network)
.\scripts\selftest.ps1
```

## Adding a New App

1. Create a directory (e.g., `my_app/`) and write your code (e.g., `main.py`).
2. Run it directly (`python -m my_app.main`) or point `app.ini` at it for the optional `App.exe`:

```ini
[app]
module = my_app.main
gui = false
# app_dir = my_app   # optional extra PYTHONPATH entry
```

3. With `-WithLauncher` built, double-click `App.exe`. `gui = true` selects `pythonw.exe` and hides the launcher console.

## Moving the Workspace

The interpreter tree is path-independent; only generated launchers are not. Full rationale and edge cases: `docs/en/architecture.md` (Chinese: `docs/zh/architecture.md`).

- `scripts/bin/shim.exe` and `App.exe` resolve everything relative to their own location.
- `python/Scripts/*.exe` launchers written by pip/uv embed absolute paths. Three triggers repair them via `scripts/repair.py`: `pip.ps1` after install, `activate.ps1` on dot-source, and `sitecustomize.py` on any interpreter start (it compares `python/.portable_root`).
- `repair.py` detects launchers by content, not size, and recovers missing entry points from the launcher payload.
- Extensionless scripts (e.g. `numba`, `jsonpointer`) are rewritten to `#!..\python.exe` only when building a release; for a moved dev workspace prefer `python -m <tool>`.
- A distributable ZIP is already self-healing: shims are generated as `shim.exe` + `<name>.entry`, and no `.bat` wrappers are produced.

## Python Version Upgrade

1. Pass `-Version` to `scripts\bootstrap.ps1`, or edit the fallback default.
2. Run `.\scripts\bootstrap.ps1` — it auto-exports current packages to `requirements.txt` and offers to restore them (`requirements.lock` first) after the engine replacement. The installed patch version is then pinned in `python/.portable_version`.
